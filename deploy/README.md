# Переезд сайта на российский сервер (VPS)

Зачем: часть российских провайдеров обрывает соединения с зарубежными хостингами (Railway
стоит в США), поэтому у части покупателей сайт не открывается («Соединение было прервано»).
Сервер в России это решает и заодно выполняет требование 152-ФЗ о хранении персональных
данных в РФ.

Займёт около часа. Лучше делать вечером или ночью: минут на 10–30 сайт будет переключаться
на новый адрес.

---

## 1. Купите VPS

Подойдёт любой российский провайдер, например reg.ru («Облачные серверы / VPS») или
Timeweb Cloud.

- Система: **Ubuntu 24.04 LTS** (подойдут и 26.04 или 22.04)
- 1 процессор, **1–2 ГБ** памяти, от 15 ГБ диска
- Регион: Москва или Санкт-Петербург

После покупки провайдер пришлёт **IP-адрес сервера** и **пароль root**.

## 2. Подключитесь к серверу

На Mac откройте «Терминал» и введите (вместо `IP` — адрес сервера):

```
ssh root@IP
```

На вопрос `Are you sure you want to continue connecting` напишите `yes`, затем введите пароль
root (при вводе он не отображается — это нормально). Можно также открыть «Консоль» прямо в
панели провайдера.

## 3. Установите сайт — одна команда

Скопируйте и вставьте в терминал сервера:

```
curl -fsSL https://raw.githubusercontent.com/FalconZWZ/twoboots-site/main/deploy/install.sh | bash
```

Через 3–5 минут появится «✅ Сайт установлен и работает на этом сервере» и IP-адрес.
Откройте в браузере `http://IP` — должна открыться главная страница магазина.

## 4. Перенесите настройки из Railway

1. В Railway откройте сервис сайта → **Variables** → **Raw Editor** и скопируйте всё.
2. На сервере выполните:
   ```
   nano /etc/twoboots.env
   ```
3. Вставьте скопированное в конец файла (в терминале Mac — `Cmd+V`). Строки `DATA_DIR` и
   `PORT`, если попадут, ни на что не влияют.
4. Сохраните: `Ctrl+O`, `Enter`, затем выйдите: `Ctrl+X`.
5. Перезапустите сайт:
   ```
   systemctl restart twoboots
   ```

## 5. Перенесите данные (каталог, заказы, клиенты, фото)

1. На **старом** сайте (`https://www.two-boots.ru/admin`) нажмите **«Резервная копия»** вверху —
   скачается zip-файл.
2. На **новом** сервере откройте `http://IP/admin`, войдите `admin` / `changeme123`, задайте
   временный пароль.
3. Раздел **«Резервные копии» → «Восстановить из резервной копии»** → выберите скачанный zip →
   **«Восстановить»**.

После этого на новом сервере всё как на старом, включая пароли администраторов и клиентов.

## 6. Переключите домен в reg.ru

reg.ru → «Домены» → `two-boots.ru` → **«DNS-серверы и управление зоной»**:

| Было | Сделать |
| --- | --- |
| `www` — CNAME → `…up.railway.app` | удалить и добавить **A-запись** `www` → `IP сервера` |
| `@` — A → `31.31.197.33` | изменить на **A** `@` → `IP сервера` |

**Записи MX, TXT и всё, что связано с почтой, не трогайте**, иначе перестанет работать
почта no-reply@two-boots.ru. Хостинг reg.ru, на котором живёт почта, тоже не отключайте.

Изменения расходятся от 5 минут до пары часов.

## 7. Включите HTTPS

Когда `http://www.two-boots.ru` начнёт открываться с нового сервера, выполните на сервере
(с вашей почтой — на неё приходят напоминания Let's Encrypt):

```
bash /opt/twoboots/deploy/install.sh ssl dmitry-sokol@mail.ru
```

Сертификат бесплатный и продлевается сам.

## 8. Проверьте

- `https://www.two-boots.ru` и `https://two-boots.ru` открываются (второй переводит на www);
- регистрация, вход, тестовый заказ; уведомление о заказе пришло на почту и в Telegram;
- в админке всё на месте.

Если между скачиванием копии и переключением DNS на старый сайт пришли заказы — посмотрите
их в админке Railway и внесите вручную. Railway держите включённым ещё неделю на всякий случай,
потом сервис можно удалить.

---

## Как это работает дальше

- **Обновления приходят сами.** Сервер каждые 2 минуты проверяет GitHub и, если вышла новая
  версия, ставит её и перезапускает сайт (занимает секунду). Если новая версия не запустилась —
  автоматически возвращает предыдущую.
- **Резервные копии** — как раньше: каждую ночь на почту и в «Резервные копии» в админке.
- Данные лежат в `/var/lib/twoboots`, код — в `/opt/twoboots`, настройки — в `/etc/twoboots.env`.

## Полезные команды (на сервере)

| Что | Команда |
| --- | --- |
| Логи сайта в реальном времени | `journalctl -u twoboots -f` |
| Перезапустить сайт | `systemctl restart twoboots` |
| Изменить настройки | `nano /etc/twoboots.env`, затем перезапуск |
| Обновить прямо сейчас | `systemctl start twoboots-update && journalctl -u twoboots-update -n 20` |
| Состояние сайта | `systemctl status twoboots` |

## Бот заявок на этом же сервере

Railway из России недоступен, поэтому бот заявок (`twoboots-botorder`) тоже ставится на VPS:

1. На Railway остановите сервис бота: два бота одновременно мешают друг другу в Telegram.
2. На сервере выполните `bash /opt/twoboots/deploy/bot.sh`. Репозиторий бота должен быть
   публичным, секретов в нём нет.
3. В `nano /etc/twoboots-bot.env` вставьте переменные бота из Railway (Variables → Raw Editor).
4. Ещё раз выполните `bash /opt/twoboots/deploy/bot.sh`. Скрипт запустит бота и переключит
   на него сайт.
5. Каждый получатель заявок один раз открывает бота, нажимает `/start` → «Поделиться номером».

Бот обновляется из GitHub сам (каждые 5 минут). Логи: `journalctl -u twoboots-bot -f`.
Если бот недоступен, сайт отправляет заказ напрямую в Telegram (`TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID`).
